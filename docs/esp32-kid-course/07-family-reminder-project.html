综合发明

家庭任务提醒器

现在把前面所有本领合起来：屏幕、按键、状态、Wi-Fi、网页和调试。

真实问题综合项目7 周计划
1项目需求

帮助谁

家人和孩子自己。提醒不要靠大声重复，而靠看得见的设备。

解决什么问题

“记得喝水”“带水壶”“收衣服”这类日常叮嘱容易忘记。

怎样算成功

任务能发送、能显示、能确认，断网时不会假装成功。

2功能清单

必须有

  • 网页发送一条任务。
  • 设备屏幕显示任务。
  • 孩子按主键确认。
  • 确认后显示“收到”。
  • 显示今天完成数量。

可以后加

  • 任务到期提醒。
  • 表情变化。
  • 家长查看完成记录。
  • 不同家庭成员不同颜色。
  • 晚上自动进入安静模式。

项目原则先把必须有做完，再考虑可以后加。

3设备状态图
状态屏幕显示什么时候变化
空闲今天完成 0 件事收到网页任务时，进入等待
等待确认新任务：喝水按主键后，进入已确认
已确认收到，完成 +1两秒后回到空闲
连接失败Wi-Fi 断开了重连成功后回到空闲
4程序结构

核心思路

state = "idle"
task = ""
done_count = 0

def receive_task(new_task):
    global task, state
    task = new_task
    state = "waiting"

def confirm():
    global state, done_count
    if state == "waiting":
        done_count = done_count + 1
        state = "confirmed"

这仍然是第 5 章学过的变量、条件、函数。项目变大后，思路不变。

分模块做

  • 网络模块：连接 Wi-Fi，接收任务。
  • 界面模块：显示任务、状态和完成数。
  • 输入模块：判断按键按下。
  • 状态模块：决定当前是空闲还是等待。

每次只调一个模块，不要一次改整个项目。

5七周制作计划

第 1 周：定需求

写下要解决的问题和必须有功能。

第 2 周：画草图

画出网页、设备和状态变化。

第 3 周：最小版本

只做“发送、显示、确认”。

第 4 周：完成计数

第 5 周：处理失败

第 6 周：美化界面

加表情、颜色和任务卡片。

第 7 周：正式使用

在家里试运行三天，记录问题。

6测试清单

正常情况

发送“喝水”，屏幕显示，按主键后计数加一。

重复点击

网页连续点两次，不应该重复计数。

断网

断开后应显示失败，不应假装收到。

重新连接

网络恢复后能重新接收任务。

7通关检查
小侦探问答：为什么要有状态？

状态让设备知道“现在该做什么”。等待确认时按键有效，空闲时按键不应该重复加一。
