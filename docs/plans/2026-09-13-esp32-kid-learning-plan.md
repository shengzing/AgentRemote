# 8 岁儿童 ESP32 学习计划

适用对象：已经学过 Scratch 图形化编程的 8 岁儿童。  
计划周期：12 个月，可按孩子状态调整为 10 到 14 个月。  
推荐节奏：每周 2 次，每次 30 到 45 分钟；其中 1 次偏概念学习，1 次偏项目实践。

配套 HTML 教程：`docs/esp32-kid-course/index.html`。教程以“家庭任务提醒器 / 留言器”为主线项目，包含 8 个互动章节、Mac 环境准备、Scratch 到硬件迁移、传感器、MicroPython、Wi-Fi 和项目展示。

## 1. 总体目标

完成本计划后，孩子应能做到：

1. 独立解释 ESP32 项目中的“输入、处理、输出”。
2. 使用图形化积木完成带按键、屏幕、灯光、声音、传感器的小项目。
3. 能看懂并小范围修改 MicroPython 代码。
4. 能完成一个简单 Wi-Fi 控制或数据展示项目。
5. 能完成一个综合项目，包括想法、草图、接线、程序、测试、展示和复盘。
6. 建立“先观察现象、再找原因、再小步修改”的调试习惯。

本计划不要求 8 岁孩子掌握 C++ 内存管理、寄存器配置或嵌入式工程体系。Arduino C++ 和 ESP-IDF 只作为后续拓展，不作为前 12 个月的主线。

## 2. 教学原则

1. **从孩子熟悉的地方开始**：Scratch 中的事件、循环、条件、变量可以迁移到硬件项目。
2. **先看见结果，再理解原理**：优先让孩子让屏幕、灯光、声音、传感器产生变化，再补充原理。
3. **少接线，多成功**：低龄阶段优先使用一体化 ESP32-S3 开发板或模块化接口，避免一开始陷入大量杜邦线故障。
4. **孩子是项目主人**：家长负责安全、烧录、复杂配置和排查；孩子负责设计、操作、描述问题和决定迭代。
5. **每次课都有可展示成果**：哪怕只是屏幕文字、一个按键事件或一次灯光变化，也要给孩子演示机会。
6. **错误是学习材料**：引导孩子说出“我预计会发生什么，实际发生了什么，我改了什么”。

## 3. 基础准备

### 3.1 器材准备

| 类别 | 推荐准备 | 说明 |
|---|---|---|
| 主控板 | M5StickS3 或类似一体化 ESP32-S3 开发板 | 自带屏幕、按键、IMU、麦克风、喇叭、Wi-Fi 等资源，适合低龄入门 |
| 数据线 | USB-C 数据线 | 必须确认是数据线，不是只能充电的线 |
| 电脑 | Windows、macOS 或 Chromebook | 用于连接开发板、烧录固件、编辑积木程序 |
| 网络 | 家庭 Wi-Fi 2.4 GHz | 第 7 个月以后用于 Wi-Fi 项目 |
| 传感器模块 | 温湿度、光线、声音、按钮、LED、舵机、超声波等 | 优先选择模块化接口；面包板套件可后置 |
| 收纳盒 | 分格收纳模块和线材 | 培养整理习惯，减少器材损坏 |
| 项目记录本 | 纸质或电子记录本 | 记录草图、现象、问题和修改过程 |

如果孩子已经有一块 M5StickC S3，也可以先使用它；本计划中的操作重点是学习逻辑和项目方法，不是绑定某一款板子。

### 3.2 Mac 开发环境和软件准备

本计划以 macOS 作为基础环境。孩子的双语言路线是：

1. **图形化 / Scratch 风格**：先用类 Scratch 积木控制硬件。
2. **Python / MicroPython**：中期开始看懂并修改 MicroPython，后期可补充普通 Python。

### 3.2.1 Mac 电脑基础要求

| 项目 | 建议 |
|---|---|
| 系统 | macOS 12 或更高版本；推荐 macOS 13+ |
| 芯片 | Apple Silicon 或 Intel 均可 |
| 内存 | 8GB 起步；16GB 更适合后期 Arduino/VS Code |
| 磁盘 | 至少保留 10GB 可用空间 |
| 浏览器 | Chrome 或 Edge；用于 Web Serial 连接开发板 |
| 权限 | 家长需要管理员密码，用于安装软件和授权 USB 访问 |

Chrome 是首选浏览器，因为 UIFlow2、MicroBlocks 等网页工具通常需要 Web Serial 或 Web USB 能力。Safari 不作为第一选择。

### 3.2.2 必装软件

| 软件 | 语言 / 用途 | 使用阶段 | 安装说明 |
|---|---|---|---|
| Google Chrome | 打开 UIFlow2 / MicroBlocks 网页工具 | 第 1 天起必备 | 用 Chrome 打开相关网页工具，并允许串口权限 |
| UIFlow2 | M5 系列积木编程、硬件控制、查看 MicroPython | 全程主线工具 | 可先用网页版；需要时可安装 M5Burner 刷固件 |
| M5Burner | 给 M5StickS3 / M5StickC S3 刷 UIFlow2 固件 | 准备阶段 | 从 M5Stack 官网下载 macOS 版本 |
| Thonny | MicroPython 编写、REPL、串口调试 | 第 5 个月起必备 | 从 Thonny 官网下载 macOS 版本 |
| Python 3 | 普通 Python 学习、网页小服务、电脑端脚本 | 第 7 个月起可选 | 从 python.org 下载安装，或由家长用 Homebrew 安装 |

### 3.2.3 可选软件

| 软件 | 用途 | 适合时间 |
|---|---|---|
| MicroBlocks for Mac | 受 Scratch 启发的实时微控制器编程环境 | 第 1 到 6 个月，可替代或补充 UIFlow2 |
| Mind+ / PictoBlox | 类 Scratch 积木编程，支持部分 ESP32 硬件 | 前 6 个月可试用 |
| Arduino IDE | Arduino C++ 后期拓展 | 12 个月后 |
| VS Code + MicroPico / PlatformIO | 家长或高年级学生后期开发 | 12 个月后 |
| macOS Terminal | 命令行、串口检查、普通 Python 环境 | 家长准备和排错用 |
| Homebrew | 家长安装 Python、开发工具 | 可选，不要求孩子使用 |

### 3.2.4 USB 和串口准备

1. 使用 USB-C **数据线**，不是充电线。
2. 插入 Mac 后，在“系统信息”里确认 USB 设备存在。
3. 可用终端命令检查串口：

```bash
ls /dev/cu.*
```

4. 如果设备没有串口，通常按板卡芯片安装驱动：

| 板卡 / 芯片 | 可能需要的驱动 |
|---|---|
| 使用 CP210x 串口芯片的板卡 | Silicon Labs CP210x VCP driver for macOS |
| 使用 CH340 / CH341 的板卡 | CH34x VCP driver for macOS |
| ESP32-S3 原生 USB 板卡 | 通常无需额外驱动 |

5. 如果 macOS 提示“系统扩展”或“安全设置”问题，由家长在“系统设置 -> 隐私与安全性”中确认。

### 3.2.5 家长安装顺序

1. 更新 macOS 并确认 USB 口可用。
2. 安装 Google Chrome。
3. 安装 Thonny。
4. 安装 M5Burner。
5. 如需要，安装 Python 3。
6. 用 M5Burner 刷入 UIFlow2 固件。
7. 用 Chrome 打开 UIFlow2，确认能连接设备。
8. 用 Thonny 选择 MicroPython (ESP32)，确认能进入 REPL。
9. 做一次最小测试：屏幕显示一行文字，或点亮一个 LED。

### 3.2.6 双语言工具分工

| 学习阶段 | 图形化 / Scratch 风格 | Python 侧 |
|---|---|---|
| 第 1-4 个月 | UIFlow2 或 MicroBlocks | 只看生成代码，不要求写 |
| 第 5-6 个月 | 继续用积木设计逻辑 | Thonny + MicroPython 修改代码 |
| 第 7-9 个月 | 用积木快速搭功能 | MicroPython + 可选普通 Python |
| 第 10-12 个月 | 项目原型 | MicroPython 主实现，普通 Python 可做网页或数据侧 |
| 12 个月后 | 可继续探索 | Arduino C++ / VS Code 作为拓展 |

开始前建议家长完成验收：

1. 安装所选编程环境。
2. 用官方文档完成一次固件烧录或板卡连接。
3. 确认 USB 串口可用。
4. 确认屏幕、按键或灯光能被点亮。
5. 准备一个不包含真实隐私信息的演示 Wi-Fi。

### 3.3 安全准备

1. 只使用 USB、锂电池模块和低压传感器，不接触市电。
2. 接线或改线前先断电。
3. 锂电池不能针刺、拆解、靠近高温；家长负责充电。
4. 不使用损坏的线材、裂开的电池或发热异常的模块。
5. 第一次使用舵机、继电器、扬声器等大电流模块时，家长必须在旁边。
6. Wi-Fi 密码、API Key 等信息由家长保管，不写入孩子的展示材料。

### 3.4 学习环境准备

1. 固定时间：每周两个固定时段，形成学习仪式。
2. 固定桌面：桌面要能放电脑、板子、模块和记录本。
3. 限制新知识数量：每次只引入 1 个新概念或 1 个新模块。
4. 使用演示语言：让孩子练习说“输入是什么、程序做了什么、输出是什么”。
5. 建立“问题卡”：孩子说不清问题时，引导写或画出“我做了什么、我想让它做什么、它现在做什么”。

## 5. 阶段 1：Scratch 到 ESP32 硬件迁移

### 时间

第 1 到第 2 个月。

### 教学目标

1. 让孩子把 Scratch 的“舞台、角色、积木、事件”映射到硬件世界。
2. 理解开发板是一台可以读取输入和产生输出的电脑。
3. 建立连接、运行、修改、展示的基本流程。

### 知识迁移表

| Scratch 概念 | ESP32 硬件概念 | 示例 |
|---|---|---|
| 当绿旗被点击 | 程序启动 | 开机后屏幕显示名字 |
| 当按下按键 | 实体按键事件 | 按下按键切换表情 |
| 重复执行 | 主循环 / 定时刷新 | 屏幕文字滚动 |
| 如果...那么 | 传感器条件 | 光线暗时打开夜灯 |
| 变量 | 计数器、状态 | 摇晃次数计数 |
| 广播 | 模块或设备间消息 | 屏幕状态变化触发声音 |

### 教学内容

1. 认识开发板：屏幕、按键、USB 口、电池、传感器、喇叭、IMU。
2. 认识编程环境：连接板卡、运行积木、保存程序、烧录固件。
3. 控制屏幕：显示文字、颜色、表情、简单动画。
4. 读取输入：按键、触摸、摇晃、倾斜。
5. 控制输出：LED、屏幕颜色、蜂鸣器或喇叭。
6. 学会三个描述词：输入、处理、输出。

### 项目任务

1. **自我介绍板**：开机显示名字、年龄和一张表情。
2. **心情切换器**：按按键切换开心、安静、生气三种表情。
3. **倒计时器**：屏幕显示 10 秒倒计时，结束时蜂鸣或变红。
4. **摇晃计数器**：每次摇晃加 1，屏幕显示次数。
5. **电子骰子**：摇晃后显示 1 到 6 的随机数。

### 掌握标准

1. 能说出“按键是输入，程序是处理，屏幕和声音是输出”。
2. 能独立连接板卡并运行或烧录程序。
3. 能修改屏幕文字、颜色、表情或提示音。
4. 能解释自己项目中至少一个事件和循环。
5. 能完整向家人演示一个小项目。

## 6. 阶段 2：传感器、逻辑与调试

### 时间

第 3 到第 4 个月。

### 教学目标

1. 帮助孩子从“按键控制”扩展到“环境感知”。
2. 理解传感器读数、阈值、条件判断和反馈控制。
3. 建立基本调试方法。

### 教学内容

1. 数字输入与模拟输入的区别。
2. 常见传感器：光线、声音、温度、湿度、加速度、按钮、超声波。
3. 阈值概念：多少算亮、多少算暗、多少算吵。
4. 显示实时数据：屏幕显示传感器数值。
5. 条件控制：达到阈值后触发灯光、声音或提示。
6. 简单状态机：待机模式、提醒模式、安静模式。
7. 调试流程：观察现象、读数据、改阈值、加提示、重新测试。

### 项目任务

1. **光线报警器**：光线变暗时屏幕提示或点亮灯。
2. **声音探测灯**：声音超过阈值时灯光闪一下。
3. **温度提醒器**：温度过高或过低时显示提醒。
4. **倾斜迷宫**：根据 IMU 方向控制屏幕角色移动。
5. **距离提醒器**：超声波检测到距离太近时提示。
6. **房间环境助手**：显示温度、湿度和舒适状态。

### 掌握标准

1. 能至少使用两种外部传感器。
2. 能解释“阈值”并尝试修改阈值。
3. 能把传感器读数显示在屏幕上。
4. 能说出项目中的至少一个条件判断。
5. 遇到问题时，能按流程描述而不是只说“它坏了”。
6. 能完成一个连续运行 10 分钟以上的传感器小项目。

## 7. 阶段 3：从积木到 MicroPython

### 时间

第 5 到第 6 个月。

### 教学目标

1. 在保留积木学习兴趣的前提下，逐步进入文本编程。
2. 让孩子理解程序不只是积木，还是可以阅读和修改的文本。
3. 掌握变量、函数、列表、循环和事件的基础用法。

### 教学内容

1. 积木生成代码：先积木实现，再观察对应 MicroPython。
2. 代码阅读：找出设置、循环、条件和输出。
3. 小步修改：改文字、改颜色、改数字、改判断条件。
4. 基础语法：变量赋值、比较、缩进块。
5. 常用结构：`while` 循环、`if/elif/else`、函数、列表。
6. 传感器接口：读取温度、按钮、IMU 或光线。
7. 错误信息入门：语法错误、缩进错误、名称错误。

### 项目任务

1. **积木改代码**：积木做灯光项目，然后在代码中修改亮度或速度。
2. **英文/中文菜单**：用函数封装显示不同菜单。
3. **简单计分器**：按键加 1，长按清零。
4. **数据记录器**：把几次温度或亮度读数保存到列表并显示。
5. **简易番茄钟**：25 分钟太长可改成 5 分钟，学习函数和循环。
6. **电子宠物**：根据时间、按键、传感器数值改变心情。

### 掌握标准

1. 能看懂一段 10 到 20 行的简单 MicroPython。
2. 能独立完成“改变量、改数字、改文字”的修改。
3. 能在指导下写一个 5 行以内的小函数。
4. 能说出变量和列表的区别。
5. 能根据错误信息尝试修改缩进、拼写或变量名。
6. 能完成一个至少包含函数和条件判断的 MicroPython 项目。

## 8. 阶段 4：Wi-Fi 与 IoT

### 时间

第 7 到第 9 个月。

### 教学目标

1. 理解设备可以通过网络发送和接收信息。
2. 建立“客户端、服务器、消息、地址”的初步概念。
3. 完成至少一个远程控制或数据展示项目。

### 教学内容

1. Wi-Fi 连接和连接失败处理。
2. IP 地址、网页、请求、响应的直观理解。
3. HTTP 控制命令：网页按钮控制 LED 或舵机。
4. 数据展示：本地网页显示温度、湿度或亮度。
5. 消息概念：指令、状态、提醒。
6. 简单 MQTT 或云端服务的可选拓展。
7. 网络安全：不公开设备地址，不上传隐私数据。

### 项目任务

1. **Wi-Fi 状态牌**：连接后显示 IP 和在线状态。
2. **网页开关灯**：浏览器按钮控制 LED。
3. **远程提醒器**：网页点击后设备震动、发声或显示提示。
4. **房间温湿度看板**：设备定时上报数据，网页显示最新值。
5. **家庭任务提醒**：家长发一条指令，孩子设备显示提醒。
6. **云端数据可视化**：把传感器数据写入简单图表服务。

### 掌握标准

1. 能在帮助下完成 Wi-Fi 配置。
2. 能解释“网页发消息，ESP32 收到后做动作”。
3. 能做一个网页按钮控制硬件的最小项目。
4. 能把一个传感器值显示到网页。
5. 能识别断网后的现象，并重新连接。
6. 能说出至少一条网络安全注意事项。

## 9. 阶段 5：综合项目与展示

### 时间

第 10 到第 12 个月。

### 教学目标

1. 从“完成课程项目”过渡到“解决真实问题”。
2. 学习项目管理：目标、方案、开发、测试、迭代、展示。
3. 培养面对复杂问题的拆解能力。

### 项目选题方法

引导孩子回答五个问题：

1. 我想帮助谁？
2. 我遇到什么问题？
3. 我的设备需要看到什么？
4. 我的设备需要做出什么反应？
5. 我怎么知道它成功了？

### 教学内容

1. 需求描述：写一句用户故事，例如“当我忘记浇水时，设备要提醒我”。
2. 方案设计：画出输入、处理、输出示意图。
3. 模块选型：屏幕、传感器、按键、声音、网络。
4. 分步开发：先单模块，再组合功能。
5. 测试与迭代：正常情况、极端情况、断电、断网、误触。
6. 展示表达：讲问题、讲方案、演示功能、讲困难。
7. 复盘记录：哪些做得好，哪些要改进，下一步想做什么。

### 综合项目候选

1. **智能浇花提醒器**：湿度过低时屏幕提醒或发送通知。
2. **学习专注盒**：学习时进入安静模式，按键后开始计时。
3. **房间天气站**：温湿度、亮度、噪音数据显示在屏幕或网页。
4. **家庭留言器**：远程发送提醒，设备按键确认。
5. **宠物喂食提醒**：定时提醒，按键后记录“已完成”。
6. **迷你桌面机器人**：IMU、表情、声音和网络提醒结合。

### 项目里程碑

| 里程碑 | 要求 |
|---|---|
| 第 1 周 | 明确问题、用户和核心功能 |
| 第 2 周 | 画草图，确定传感器和输出方式 |
| 第 3 周 | 完成最小可运行版本 |
| 第 4 周 | 增加第二个功能或优化体验 |
| 第 5 周 | 完成测试和修复 |
| 第 6 周 | 制作展示页或演示流程 |
| 第 7 周 | 正式展示和复盘 |

### 掌握标准

1. 能独立说出项目要解决什么问题。
2. 能画出输入、处理、输出结构图。
3. 能把项目拆成 3 到 5 个可完成步骤。
4. 能使用传感器、程序逻辑和至少一种网络或输出能力。
5. 能完成测试并描述至少一个 bug 的解决过程。
6. 能向不熟悉编程的人完整展示项目。

## 10. 每周教学流程

3. 做一个微练习，10 到 15 分钟。

## 11. 评估方式

不建议只做纸面考试。建议每阶段使用四项评估：

| 评估项 | 问题 | 证据 |
|---|---|---|
| 概念理解 | 能说出输入、处理、输出吗？ | 口头解释或画图 |
| 操作能力 | 能连接、修改、运行程序吗？ | 现场操作 |
| 调试能力 | 能描述问题并尝试修复吗？ | 问题记录 |
| 项目表达 | 能向别人展示项目吗？ | 展示或视频 |

每个阶段结束可以做一次“家庭答辩”：

1. 孩子展示项目。
2. 家长提出两个问题。
3. 孩子演示至少一次修改或调试。
4. 孩子说出下一步改进。

## 12. 常见风险和应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 太早学 C++ | 孩子觉得难、只想复制代码 | 先完成积木和 MicroPython 阶段 |
| 接线过多 | 程序没问题但硬件不工作 | 使用模块化接口或一体化板 |
| 项目太大 | 孩子失去兴趣 | 拆成每次能完成的小步骤 |
| 家长代做太多 | 孩子不会表达自己的项目 | 家长只做安全和复杂配置 |
| 调试挫败感强 | 一直失败、不想继续 | 回到最小例子，先让一个灯或一行文字成功 |
| 网络问题 | Wi-Fi 不稳定导致项目失败 | 先离线完成逻辑，再单独处理网络 |

## 13. 后续拓展

完成 12 个月计划后，可以选择：

1. **Arduino C++ 路线**：学习 `setup()`、`loop()`、GPIO、PWM、中断、串口调试。
2. **更完整的 IoT 路线**：学习 MQTT、服务端数据存储、图表、通知。
3. **机器人路线**：学习舵机、底盘、电源、运动控制。
4. **语音/摄像头路线**：在性能更好的 ESP32-S3 上学习音频或图像项目。
5. **产品化路线**：学习外壳设计、电池管理、稳定性测试和用户反馈。
